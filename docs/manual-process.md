# Manual public-notice process

This is a working outline reconstructed from the supplied GIS process notes and subsequent project decisions. It describes handoffs and files, not a legal notice checklist. Confirm current notice methods, recipients, responsibilities and vendor requirements with the business team.

| Step | Movement / action | Typical output |
|---|---|---|
| 1 | Planner sends the case number, notice letter, requested method and supporting details to P&DS GIS by email. Some Historic Preservation requests historically came through a board secretary; the exact routing still needs confirmation. | Case request and letter |
| 2 | P&DS GIS opens the map template, finds the case polygons, prepares the vicinity map and case link/QR. | Draft VM |
| 3 | P&DS GIS emails the map to the planner. Planner confirms the subject location or returns corrections. GIS revises and resends as needed because case geometry is not always correct. | Approved subject map |
| 4 | Following approval, P&DS GIS selects county owner records using the instructed method. Adjacent/custom selections require manual adjustment, including across-street parcels when appropriate. | Raw selected feature class and DBF |
| 5 | P&DS GIS cleans/formats the mailing fields, applies approved exclusions/institutional substitutions and combines matching destinations. | ML spreadsheet and mailing count |
| 6 | The operator assembles the letter and vicinity map, then emails the notice package and ML spreadsheet to the mailing vendor. Planner/vendor replies may require corrections and another handoff. | PN2 and ML sent to vendor |
| 7 | The operator combines the mailing-record package, saves the files, records status/counts, uploads the package to the EnerGov case and completes the notification workflow step. | PN3 and EnerGov close-out |

The historical notes assign many operating steps to GIS; responsibility for future planner self-service and final review is not settled here. No staff accountability policy is invented by this document.

## File terms from the existing process

- **PN:** notice letter.
- **VM:** vicinity/location map.
- **ML:** mailing list; spreadsheet supplied to the vendor.
- **PN2:** assembled letter/map mailing package, as described in the operations notes.
- **PN3:** combined records package including the mailing-list PDF for EnerGov.

The code currently generates VM and ML outputs. PN/PN2/PN3 assembly, email, postal fulfillment and EnerGov work remain manual.
